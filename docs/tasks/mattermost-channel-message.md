# Private-channel message, send and reread

The maintainer approved this four-step live page scenario and its evidence rules
on 2026-11-22. Use the existing public Mattermost pilot, unmodified Team Edition
11.11.4 and the existing Refract interfaces. Select only e2e. Use one ordinary
member in one disposable private channel. The reviewed declaration has format 1.

1. Open the channel and check its path and visible composer.
2. Fill the composer and read back its value.
3. Click the send control once. Require one associated POST to the posts endpoint,
   status 201, an observed message ID, and the expected member, channel and text.
4. Load the same channel as a new document in the same session. Check its path,
   identifiable rendered message rows, exactly one occurrence of the returned ID,
   and the visible text of that same row.

Bind the three environment values before execution, independent of the send
response. Freeze the reviewed declaration and bound inputs. A new run uses a
new message. Project both the row identity and its countable ID field from the
actual rendered row, retaining duplicates. Never populate page facts from the
response, expected values, optimistic UI, list position or socket notifications.
Preserve native outcomes. Where observation or association is unavailable,
record the affected business obligation as unverified. A complete observation
that contradicts an expectation is a failed obligation.

Retain evidence and environment-specific values locally. Publish only reusable
code, neutral inputs and a reviewed aggregate. Record integration, automated
waiting, human review rounds, and unavailable measurements separately. Check
same-text/wrong-ID, duplicate identity and missing evidence controls. Audit the
four-step result independently before acceptance and release. No core, browser
helper, declaration language or target changes are in scope.
